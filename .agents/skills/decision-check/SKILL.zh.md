# decision-check：决策合规检查

[English](/.agents/skills/decision-check/SKILL.md) | 中文

只回答一个问题：**这次要做的事，违反了哪条现行决策？**

读取记录时遵循[工作流契约](/.agents/se/contracts/workflow.zh.md)：请求文件夹里只有 `proposal` 配对是记录，`discuss-*` / `reply-*` 是非约束性证据；最终批准在人与提案作者的直接对话中。评审贡献与回复格式见[记录格式契约](/.agents/se/contracts/note-format.zh.md)，只读技能不改证据或记录。保留分歧，不把作者回复或门禁通过当作审阅者确认。

## 检查范围：只管「机器查不出、人也看不穿」的约束

不是所有决策都该在这里过一遍。先分流，避免把检查退化成仪式：

| 破坏是怎么被发现的 | 需要什么 | 本技能管不管 |
|---|---|---|
| 测试、lint、门禁、类型 | 写好检查即可 | **不管**——机器会开火 |
| 人看 diff 一眼就懂 | 一句话进 `AGENTS.md` 常驻 | **不管**——已常驻 |
| 要读完整决策 + 结合上下文才判断得出 | 本技能 | **管** |

一条约束如果一句话就能说清且违反了看得见，它应该已经在 `AGENTS.md` 里，不需要每次报告。**只在第三种情况下运行本技能。**

## 输入

二选一：

- **提案**：决策树 `proposed/` 生命周期下的一篇记录（或即将写入的草案）
- **改动**：命令产出，或实际的 `git diff`

## 步骤

1. 读[记录格式契约](/.agents/se/contracts/note-format.zh.md)，然后遍历 `implemented/` 与 `proposed/` 的记录。
2. 按 `## 作用域` 筛出管辖本次对象的决策。**作用域外的决策不看**——新代码没有锚点，只能靠作用域命中。
3. 对每一条命中的决策判断三态。

## 三态与判定

| 状态 | 判定 | 下一步动作 |
|---|---|---|
| **确定违反** | 有明确依据说明伤及约束面 | 阻塞：改实现，或走 `decision-revise` 改决策 |
| **不确定** | 找不到依据排除，但也确认不了 | 交人裁断——**必须提出一个具体问题** |
| **确定不违反** | 有依据说明不受管辖，或只是换实现 | 通过 |

**「不确定」是合法且被鼓励的答案。** 宁可说不知道，也不要为了给出干净结论而编一个「通过」。

## 输出

只有两种形态。**通过就一行，不列检查了什么。**

### 通过

```
check: 通过
```

不写「已检查 22 条」，不给覆盖计数——那是不可验证的主张，和没写一样。真要判断有没有看，看 diff 更快。

### 有项

```
check: 阻塞

[违反] <记录路径>
  位置: packages/adapter/src/handler.py:88（新增）
  依据: 作用域为「一切请求处理路径」；本处新增同步磁盘写，决策无豁免记录。

[不确定] <记录路径>
  位置: packages/adapter/src/anon.py:41（修改）
  依据: 决策只列了白名单，未定义未列出类型的兜底边界。
  待裁: 新段类型 "xxx" 应归入白名单，还是按「其他消息」留类型标记？
```

四要素：**标签 → 记录路径 → 位置 → 依据**。`依据` 必须同时说清「约束管到哪」和「这处做了什么」，只说一半等于没依据。

`[不确定]` 必须多一行 **`待裁:`**，而且必须是人的一个具体问题。没有它，不确定就是不可执行的状态转移，人会回一句「你自己判断吧」，流程就崩了。

### 混合与排序

- 违反在前，不确定在后。
- 同一决策多处违反合并成一项，位置写多个。
- **上限 5 项。** 超过说明改动太大，应该先拆分——这个上限是信号，不是格式要求。

## 覆盖但未违反时

**不报告。** 进入本技能的决策本来就少，`check: 通过` 足够。

代价是：若这里判断错了，没人能发现「agent 认为它不违反」这个判断本身。防线是「不确定」这个状态——它要求 agent 主动承认不知道。

## 输出落在哪

| 场合 | 落点 |
|---|---|
| agent 回应 | 直接输出，**不写文件** |
| 阻塞 / 需裁断 | 停在这里等人回话；**不改代码、不提交** |
| 通过且要走 PR | 顶部写进 PR 描述 |

不生成检查报告文件——会腐化，且没人读。

## 边界

- 只读。修订、重构、补记录都要后续授权。
- 不替代语言层代码审查和文档一致性检查。
- 「无触达 / 重推导 / 受限」这类分类**不使用**：它们都通向「继续」，零信息。
