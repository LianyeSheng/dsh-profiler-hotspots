# 双语文档

[English](/.agents/se/contracts/i18n/README.md) | 中文

范围内每篇文档都以英文和简体中文维护，因为本仓库同时由使用两种语言的读者与 agent 阅读。本页定义配对约定、门禁、范围与排除，以及分工；[translation-rules.zh.md](/.agents/se/contracts/i18n/translation-rules.zh.md) 定义如何翻译；[terminology.zh.md](/.agents/se/contracts/i18n/terminology.zh.md) 是术语真源。日常工作遵循下列规则；扩展版 [update-bilingual-docs](/.agents/skills/update-bilingual-docs/SKILL.md) 工作流只在用户显式调用时运行。

## 配对约定

- **两种语言同权。** 变更可以用任一语言撰写，被编辑的一侧就是本次更新的源，对侧文件说同样的话。两个文件谁也不高于谁。记录键取自英文标题 slug，因此英文文件是记录寻址的锚点，而不是内容权威。
- **一对文档是三个同目录文件。** 英文 `foo.md`、中文 `foo.zh.md`，加一份一致性记录 `foo.i18n.yaml`，都在同一目录。不用语言目录，不用独立翻译仓库，不用中英混排的单文件。配对整体合并：一次变更不会只带一种语言而缺其余两个文件。
- **一致性记录。** `foo.i18n.yaml` 为每个标题小节保存一个条目，键是该小节英文标题 slug 组成的路径（第一个标题之前的文本为 `/`；重复路径依次加 `~2`、`~3`……）。条目保存该小节中每一侧内容的 hash：该小节的行按文档顺序拼接，排除围栏代码块、开头 YAML frontmatter 与语言切换行，标题行仍计入；先裁掉小节首尾的空白行，再把成对文档的链接目标替换为 `pair:/<锚点路径><query/fragment>` 形式的中立标记。目标只要落在范围内的成对路径上就归一，与对侧文件是否已在磁盘上无关，因此同一对文档在安装前后得到相同的记录。最后取 SHA-256 的前 16 位小写十六进制。

  ```yaml
  /foo:
    en: 41d772192075e133
    zh: dda91c6c670cfd9d
  /foo/usage:
    en: 86940bea4a3c7ed6
    zh: de78429597783c7f
  ```

  文件以不含路径的固定头注释开始；条目按文档顺序、以上面三行的形式排列。围栏代码块不参与 hash，因为 P4 已要求两侧逐字节一致；语言切换行也不参与，因为安装会把它的目标改写为安装后的对侧。一侧的第 `i` 个小节对应另一侧的第 `i` 个小节。修改不同小节会落在记录的不同行上，Git 默认文本合并能组合它们；只有两个分支改了同一小节时，记录才会冲突。失去同步的配对按被改一侧的 diff 对另一侧打最小补丁，从不整篇重译；门禁会指出每个变化的小节。
- **语言切换行。** H1 之后恰好一个空行——H1 在第 1 行时切换行就在第 3 行——英文文件写 `English | [中文](/<path>/foo.zh.md)`，中文文件写 `[English](/<path>/foo.md) | 中文`。切换行与 H1 之间多出空行是 P3 失败。目标是对侧文件的仓库根相对路径。安装前维护在源码树中的配对把切换行指向身边的对侧；安装会渲染出安装副本，并把目标改写为安装后的对侧。两个方向都保留互链：中文文件不得省掉英文回链，英文文件不得省掉中文链接。
- **结构与对侧一一对应。** 标题深度与顺序、围栏代码块（信息字符串与内容逐字一致）、表格行列数、列表（每一层缩进的类型、有序起始编号与条目数），以及保留原样 query/fragment 后缀的语义链接目标，两侧一一对应。指向成对文档的链接遵循 P5 的 locale 规则。开头 YAML frontmatter 例外：两侧可以携带不同的 frontmatter，因为它既不参与结构镜像，也不参与小节 hash。完整保持规则见 [translation-rules.zh.md](/.agents/se/contracts/i18n/translation-rules.zh.md)。

## 受支持的 Markdown 子集

配对只分析固定的 Markdown 子集：ATX 标题、围栏代码块、分隔行与表头列数一致的 GFM 表格、紧凑与松散列表、行内链接与引用式定义，以及内联图片（图片目标按 `image:` 结构项参与比较；引用式图片定义不与正文区分）。

门禁不支持、也不承诺支持：setext 标题（报 P4）、缩进代码块、跨行的行内链接，以及 HTML 块；HTML 注释不参与结构分析，但仍计入 P2 哈希。开头 YAML frontmatter 被容忍：文档以 `---` 行开头且其后存在一行 `---` 时，这些行不参与结构比较，也不参与小节 hash，且从不作为围栏代码块比较，因此两侧可以携带不同的 frontmatter。不是文档开头的 `---` 行，或没有结束行的开头 `---`，都按普通文本处理。

## 门禁：verify-translation-pairing

`node .agents/se/scripts/docs/verify-translation-pairing.ts` 机械地强制执行本约定。它通过 Node ≥ 24 的原生类型剥离运行，没有依赖。

- 无参数检查全语料。
- `--list` 打印每篇文档的配对状态——`ok`、`missing` 或 `out-of-sync`——并为每个被排除路径旁的残留配对产物打印一行 `excluded-artifact <path>`。它不因配对状态失败；配置错误仍以 `2` 退出。
- 位置参数只检查被点名的配对：配对的三个文件之一，或其去后缀 stem，都能点名它。点名的配对不在范围、被排除或在磁盘上三件套全不存在时，按用法错误退出 `2`，不算通过。
- `--write <pair...>` 重录被点名的配对；`--write --all` 重录两份语言文件都存在的一切配对，缺记录时创建记录，缺少任一侧语言文件的配对跳过。点名的配对不完整、不在范围或被排除时，按用法错误退出 `2`；内容无法重录的配对（例如两侧标题节数不一致）同样以 `2` 拒绝。产出的一致性记录 diff 就是可评审的「确认一致」动作，因此批量重录必须显式写成 `--all`。

退出码：`0` 全部检查通过，`1` 至少一条发现，`2` 用法或配置错误。

<a id="p1"></a>

### P1 完整配对

范围内每篇文档都有三个文件。被 manifest 排除的文件没有 `.zh.md`，也没有 `.i18n.yaml`；全量检查会报告任何残留，`--list` 把它们打印为 `excluded-artifact` 行。

<a id="p2"></a>

### P2 一致性记录

记录为规范形式，其条目等于根据当前内容计算出的条目。任一侧的语言特有内容改了而没有重新确认配对，检查就变红。

<a id="p3"></a>

### P3 语言切换行

切换行位于 H1 之后恰好一个空行处——H1 在第 1 行时即第 3 行——中文文件链回英文文件，英文文件链向中文文件。切换行与 H1 之间多出空行是 P3 失败；具体写法见「配对约定」。目标是对侧路径：已安装的配对指向安装后的对侧，安装时渲染的配对指向对侧的源码路径。

<a id="p4"></a>

### P4 结构镜像

两侧在标题深度与顺序、围栏代码块（信息字符串与内容逐字节一致）、表格行列数、列表（每一层缩进的类型、有序起始编号与条目数），以及保留原样 query/fragment 后缀的语义链接目标上一致。

<a id="p5"></a>

### P5 成对文档链接 locale

解析后指向范围内成对文档的链接使用所在侧的 locale：英文侧用 `.md` 路径，中文侧用 `.zh.md` 路径，并且必须写成仓库根相对、带前导 `/`。目标是否算作成对文档由范围规则决定，与对侧是否已安装无关。范围内缺少对侧是配对完整性问题，不是回退。指向成对语料之外目标的链接不在 P5 检查范围，它们的仓库根相对形式由仓库链接门禁负责。语言切换行是显式的跨 locale 例外。

每条发现都带规则 ID，其「契约」行指向本页的 `.agents/se/contracts/i18n/README.md#p1` … `#p5`。每次运行都以本仓库门禁统一要求的「未自动检查」段结束，全绿时也输出：

```
✗ .agents/se/contracts/i18n/README.zh.md:1  [P3]
  发现：H1 后的第一段不是规范的语言切换行
  期望：[English](/.agents/se/contracts/i18n/README.md) | 中文
  修复：在 H1 之后空一行写入 [English](/.agents/se/contracts/i18n/README.md) | 中文
  契约：.agents/se/contracts/i18n/README.md#p3

未自动检查（4 项，需 review）
  R1 译文忠实性   R2 术语一致性   R3 中文自然度
  R4 行内代码、列表与表格顺序、图片替代文本与呈现、强调
  清单：.agents/se/contracts/i18n/translation-rules.md
```

该段点明门禁查不了什么：两侧是否在说同样的话、术语是否符合术语表、中文是否读起来自然，以及结构签名没有编码的那些结构——行内代码、列表与表格顺序、图片替代文本与呈现、强调。

门禁带来的实际规则是：**修改配对文档任一侧的变更，必须在同一次改动里更新对侧，并用 `--write <pair>` 重新记录该配对。** 留下失去同步的配对，检查就失败。

门禁的限制很明确：**通过门禁只意味着这组文档在当前内容上被确认一致，不代表这次确认可靠。** 它检查记录的 hash 与 Markdown 结构；它无法判断两侧是否在说同样的话，也无法判断措辞是否准确、术语是否得当、行文是否自然。这部分由评审负责，标准见 [translation-rules.zh.md](/.agents/se/contracts/i18n/translation-rules.zh.md)。重新记录了但译文潦草的配对能通过门禁；它不得通过评审。

## 范围与排除

决策记录树中的请求文件夹包括 proposal、每个 `discuss-<topic>` 意见和同 slug 的 `reply-<topic>`；每项均为完整的英文／中文／记录三件组。证据不享有仅英文豁免。生命周期迁移携带所有三件组，同时修复切换行、当前链接与记录头部；冻结归档保留三件组，不重录。

范围包括：任意目录中文件名为 `README.md` 的文档（大小写不敏感）；`docs/` 下的所有活跃 `.md` 文件；[格式契约](/.agents/se/contracts/note-format.zh.md)所定义的决策记录树中的所有活跃 `.md` 文件，其冻结归档除外；`.agents/se/` 下的所有 `.md` 文件；以及 `components/` 下的所有 `.md` 文件，各组件单语的 `agents.md` 片段除外。仓库根部的 `archive/` 目录是另一棵树，仍在范围内。新增目录或新 README 无需修改 manifest 就进入范围。

范围由发现规则决定，不靠文件清单。既不是 README、也不在上述根下的路径不在范围内：技能文档（`.agents/skills/**/SKILL.md` 及其旁边的 `references/` 与 `assets/` 文件）与模板（`.agents/se/templates/**/*.tmpl`）都不匹配 `.md` 源规则，单语的组件 `agents.md` 片段按名排除。这些路径因发现规则到不了而不在范围内，不是因为 manifest 排除了它们。

**发现排除。** 门禁不扫描依赖、构建与被忽略的目录树：`node_modules/`、`.git/`、`dist/`、`lib/`、`.pnpm-store/`、`coverage/` 与 `.cache/`、`.tmp/`，与 `.agents/se/scripts/docs/translation-pairing.ts` 的 `NON_SOURCE_DIRECTORIES` 一致；嵌套目录同样按名命中。这些树不是 manifest 排除项，也不做产物检查。

**manifest 排除。** [清单](/.agents/se/scripts/docs/translation-pairing.manifest.json)只显式排除本项目自己的文档写作指令 `docs/AGENTS.md`：它按设计只有单一语言，不属于交付载荷。只有该路径必须没有 `.zh.md` 与 `.i18n.yaml`；全量检查报告任何残留，`--list` 把它们打印为 `excluded-artifact` 行。决策记录树的冻结归档子树仍不在范围内，但归档的决策记录保留完整的中英三件套：门禁既不要求也不重写这些文件，来自成对文档、指向归档记录的链接按 locale 中立形式归一，使两侧都能引用它。清单只含显式排除项：没有逐文件推进清单、日期分界或 README 专用政策类别。

**统一要求**：当前及今后纳入范围的每篇文档——包括决策记录与 README——合并时都必须构成完整配对。

## 分工

日常更新由做改动的 agent 直接完成：先加载 [terminology.zh.md](/.agents/se/contracts/i18n/terminology.zh.md)，再单遍更新两侧。它不调用翻译技能、不生成 briefing、不另起一轮翻译评审，也不委派 subagent。例程路径就是本契约：在同一次改动里更新两份语言文件，按被改一侧对另一侧打最小补丁，保持结构与 locale 规则，然后重录该配对。决策记录与 README 也是成对文档，改动它们走同一条例程路径。

扩展版 [update-bilingual-docs](/.agents/skills/update-bilingual-docs/SKILL.md) 工作流只在用户显式调用时运行：读取真源、逐小节对照、补丁式修改对侧、校验代码块与结构、重录、报告查了什么与没查什么。它不改变例程路径，也不放宽配对约定。

翻译质量由评审负责：语义忠实性、术语、自然度，以及结构签名没有编码的结构要求。门禁的「未自动检查」段就是评审必须覆盖的固定清单。
