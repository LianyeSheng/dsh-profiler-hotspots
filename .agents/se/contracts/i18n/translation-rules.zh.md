# 翻译规则

[English](/.agents/se/contracts/i18n/translation-rules.md) | 中文

本文规定如何在一对文档的两侧之间翻译。两种语言同权（见[配对约定](/.agents/se/contracts/i18n/README.zh.md)）：被编辑的一侧就是本次更新的源。**必须（MUST）**／**禁止（MUST NOT）** 会卡合并或评审；**应当（SHOULD）** 偏离要说明理由；**可以（MAY）** 自行裁量。

## 忠实性

- 对侧文件*必须*传达撰写侧说的内容：不添加，也不遗漏。两侧实质不一致时，修正错误的一侧，并在同一次变更里把另一侧带上。
- 对侧文件*应当*读起来是目标语言自然的技术文字，而不是逐词对照；保持原作者的语域，简练的保持简练。
- 目标语言会让执行主体含糊时，补出显式主语；中文写实际执行者（系统、门禁、评审人），不用含糊的被动句。

## 结构与代码

- 标题深度与顺序保持不变；标题文字要翻译。列表（每一层缩进的类型、有序起始编号与条目数）、表格行列数两侧一一对应。不得增删、重排或合并小节。受支持的 Markdown 子集见[配对约定](/.agents/se/contracts/i18n/README.zh.md)。
- 围栏代码块*必须*逐字节一致，包括注释与信息字符串；代码从不翻译。行内代码——命令、flag、配置键、路径、事件名、API 名、版本号——原样保留。
- 解析后指向范围内成对文档的链接使用源侧 locale：英文侧 `/<path>.md`，中文侧 `/<path>.zh.md`，一律带前导 `/`。query 与 fragment 后缀原样保留；成对语料之外的目标保留原路径；外部 URL、图片与页内 fragment 不变；链接文字要翻译。

## 术语

- [terminology.zh.md](/.agents/se/contracts/i18n/terminology.zh.md) 是双向的术语真源。翻译前先加载；表内每一行都生效，包括用法约束。
- 译成中文时，使用「中文」列与首现括注。术语表未收录的技术术语保留英文，除非有可引用的中文通行译法；不得自行造词。确定后的术语在同一次变更中进入术语表。
- 译成英文时，使用通行的英文术语，不加中文括注。

## 中文排版

- 中文与拉丁词之间、中文与数字之间各留一个半角空格：`每个 plugin 注册 3 个 tool`。禁止全角数字或全角拉丁字母。
- 中文行文使用全角标点：`，。：；？！（）「」`。半角标点保留在代码内、按原样引用的完整英文句子内，以及数字内（如 `3.5`、`1,024`）。
- 并列项之间用顿号（、）；优先用冒号、句号、逗号或括号，尽量不用破折号。第二人称用「你」，不用「您」。
- 强调标记落在与对侧相同的文字段上。一个段落一个物理行，文件末尾恰好一个换行。

## 补丁式更新

- 按被改一侧的 diff 对另一侧打最小补丁，然后重录。禁止整篇重译：那会丢掉改动之外已经评审过的措辞。
- 首现括注随内容移动：括注写在该术语现在首次出现的位置，术语消失时一并消失；每个文件只写一次。
- 重录之前单独读一遍打补丁后的对侧文件；diff 之外的内容保持已评审的措辞。

## 质量标准

- 一对文档的完成标准：双语工程师只读任一文件，能获得与另一文件读者相同的事实、告诫和语气，并且没有多余内容。
- 对每对被点名的文档运行 `node .agents/se/scripts/docs/verify-translation-pairing.ts <pair>`，PR 层面运行全语料检查。门禁会声明它没有检查什么——R1 译文忠实性、R2 术语一致性、R3 中文自然度、R4 行内代码、列表与表格顺序、图片替代文本与呈现、强调；这四项与语气由评审负责。
