# 锚点与链接契约

[English](/.agents/se/contracts/anchor-convention.md) | 中文

> 规则 ID 与 `.agents/se/contracts/note-format.md` 同一套编号空间。链接与锚点的唯一本。

## 为什么需要锚点

**你无法在选择上下文之前知道该选什么上下文。** 任何「先读对的东西再动手」的指令，都要求 agent 具备它还没有的信息。

打破这个循环的唯一方法，是**把索引放在被读之物身上**。代码注释不是文档，是索引条目。

---

## 一、什么时候在代码里留锚点

### J4 触发条件（由 review 执行，机器查不了）

代码里出现下面这种情况，必须写一句为什么 + 链接：

> **显然可以更简单、更直接，但偏偏没这么做。**

读者看到会问「为什么这里要绕一下」——那就是该写锚点的位置。

**不写锚点的三种情况：**

| 情况 | 理由 |
|---|---|
| 已被 lint / 门禁 / 测试机械拦住 | 门禁会开火，比注释强 |
| 代码形状本身已经说明（类型签名、常量名） | 再写一遍是噪音 |
| 只是「属于某条决策的作用域」 | 那是 `decision-check` 的职责，不是索引的职责 |

**判据收紧成一句：读者会合理地想改这段代码，且有决策禁止或限定这种改法。**

## 二、锚点的形态

### A3 形态

一行，包含**为什么** + **指向记录的仓库根相对路径**：

```python
# 故意保留同步读：日志已改异步刷盘，磁盘抖动风险已消除；放宽条件与实测数据见
# .agents/notes/implemented/architecture/2026-09-03-hot-path-sync-io.md
```

三要素，缺一不可：

1. **为什么**（一句，让读者能判断「这次条件变了没有」）
2. **链接**（仓库根相对路径，无前导 `/`）
3. **位置**（放在约束实际被执行的模块或函数附近，不是文件顶部）

### A4 只写禁令不合格

```python
# 不要删除这个判断          ← 不合格：读者不知道为什么，遇到「更聪明的改法」就失效了
```

```python
# 故意保留：合并转发必须递归补全到 5 层，否则嵌套卡片会丢内容
# 见 .agents/notes/implemented/feature/2026-09-30-forward-depth.md   ← 合格
```

**只写禁令的注释会被「更聪明的改法」推翻**。写了 why，读者才能判断这次的条件变了没有。

## 三、链接

### L1 解析基准是仓库根

仓库内的一切引用按**仓库根**解析，不按当前文件解析。

这是唯一约定。它消除了「文件移动导致链接失效」这一类问题中的一半——**代码文件自己移动时锚点不失效，只有被引用的记录移动才失效。**

### L2 Markdown 内链带前导 `/`

```markdown
[rationale](/.agents/notes/implemented/architecture/2026-09-03-x.md)
```

前导 `/` 是 GitHub 解析仓库根的要求。不带会被当成相对当前文件。

**反例**：`[x](.agents/notes/x.md)` 在 `.agents/se/` 下的文件里会解析成 `.agents/se/.agents/notes/x.md`，静默断链。

### L3 链接目标必须存在

`python3 .agents/se/scripts/decisions/verify_links.py` 全仓扫描，解析失败即报错。

**扫描范围**：全仓所有文本文件，不是只扫 `notes/`。散落在各处的 markdown、代码注释、脚本注释都在范围内。

### L4 被引用文件本次有改动 → 提示（不阻断）

若某个链接的目标文件出现在本次提交的改动文件集合中，输出一条 **warning**：

```
被引用的文件在本次提交中有改动，确认代码注释中的说明仍然成立
```

理由：链接有效性是纯机械的，但**复述是否仍然成立是语义的**。这条把「陈旧锚点」的发现从周期性巡检变成触碰时提示——**感知发生在触碰的瞬间，不做周期清点**。

严重度是 warn 不是 error：链接有效但语义可能变了，不该阻断提交。

## 四、门禁行为

`python3 .agents/se/scripts/decisions/verify_links.py` 的检查项：

| ID | 检查 | 严重度 |
|---|---|---|
| L2 | Markdown 内链是否带前导 `/` | error |
| L3 | 链接目标是否存在 | error |
| L4 | 被引用文件是否在本次改动中 | warn |

**解析规则（唯一一条）**：

```
对每个仓库内链接：
  外部 URL（http/https/mailto）、页内锚点（#...） → 跳过
  以 / 开头 → 去掉前导 /，按仓库根解析
  代码注释中的 .agents/... 路径 → 按仓库根解析
  否则 → 报 L2（应为仓库根相对）
```

**扫描范围**：全仓所有文本文件（markdown、代码注释、脚本注释），不只是 `notes/`。

**排除项**：`node_modules` 等构建产物目录、`test` / `tests` / `__tests__` / `fixtures` 目录，以及 `*.test.*` / `*.spec.*` 文件。测试里的 `.agents/notes/...` 多为合成路径，不指向真实记录。

**严重度分工**：`L2` 在 `.agents/se/`、`.agents/notes/`、`.agents/skills/decision-*` 内是 error，在其他位置是 warn。`L3` 全局是 error，因为坏链无论在哪都是坏的。

## 五、断链的三个原因与处置

| 原因 | 门禁能做的 | 处置 |
|---|---|---|
| 被引用记录发生生命周期迁移 | 报出位置与目标 | agent 用 `find` 定位新路径并修正 |
| 记录被合并或删除 | 报出位置与目标 | 人工确认去向 |
| 手误写错 | 报出位置与目标 | agent 修正 |

**门禁只报定位，不猜修复。** 猜错比不猜更坏——agent 会照着错误的建议改。
