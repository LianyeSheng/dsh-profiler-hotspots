# 复查清单

[English](/.agents/se/contracts/review-checklist.md) | 中文

> 机器检查不了的三件事。门禁每次运行都会声明它没有覆盖这些，本清单是它们的家。

文档门禁 `python3 .agents/se/scripts/decisions/verify.py`（含 `document_validation.py`）全绿**不等于**记录合格。它只保证形状对；下面三件事只有读者能判断。

---

## J1 只有决策变化才写记录

**问题**：这次改动改变了「必须一直满足什么」吗？

| 情形 | 写不写 |
|---|---|
| 决策变了（新增约束、放宽约束、推翻约束） | **写** |
| 纯实现替换（约束没变，只换做法） | **不写** |
| 机械改动、局部编辑、局部 UI 调整 | **不写** |
| 修 bug 但暴露出「原来我们一直该满足某条约束」 | **写** |

**不写的理由**：记录树的量级必须停在「决策数」，不能变成「提交数」。几千篇记录里，真正该反复读的几十条会被淹没。

**写错的代价**：写多了 → 记录被稀释，没人读；写少了 → 下一个 agent 重新发明你已经想清楚的东西。

---

## J2 一条记录 = 一条可独立判定「何时被违反」的约束

**自检问句**：能不能说清「什么情况下这条被违反了」？

- 能 → 合格
- 不能（「系统应当简洁」）→ 退回 `## 问题` 层，它还不是决策

**为什么**：可判定性是决策和愿望的分界线。愿望无法被违反，因此也无法约束任何实现。

**常见不合格形态**：

| 不合格写法 | 问题 | 改法 |
|---|---|---|
| 「系统应当简洁」 | 无法判断何时违反 | 写成具体断言，或退回问题层 |
| 「注意性能」 | 没有阈值、没有范围 | 写成 p99 ≤ 50ms + 作用域 |
| 「所有模块都要…」 | 作用域没界定 | 说清哪些模块 |
| 一条记录里塞了三条互不相关的约束 | 无法独立判定 | 拆成三条 |

---

## J3 备选方案是真实备选，不是稻草人

**自检问句**：这些备选里，有没有一个是我当时真的在犹豫的？

- 有 → 合格
- 全是明显的坏主意 → 不合格，你在给结论化妆

**好备选的特征**：它有一个真实的、你会为之让步的优点。写出来的形式是「它赢在哪，但因此输了什么」，不是「它错在哪」。

**反例**：

```markdown
- **用随机数决定架构。** 否决：太荒谬。
```

**正例**：

```markdown
- **每条决策一个编号，编进单一台账。** 否决：编号是全局计数器，并行工作时是协调点，
  而且被指向的文件一移动就断链。但它赢在「短引用」——`#7` 比一长串路径好写，
  这一点我们靠「代码注释里只留一句复述 + 路径」部分补偿。
```

## 复查的输出

复查不产出分数，只产出**阻塞项**：

```
复查：2 项阻塞

[J2] .agents/notes/implemented/process/2026-10-01-x.md
  `## 决策` 写的是「注意日志量」，无法判定何时被违反
  → 改成具体断言，或退回 `## 问题` 层

[J3] .agents/notes/proposed/architecture/2026-10-20-y.md
  `## 考虑过的替代方案` 只有一条明显荒谬的备选
  → 补一条你当时真的在犹豫的，或说明为什么没有
```

无阻塞时输出一行 `复查：通过`。

## 谁执行

| 场合 | 执行者 |
|---|---|
| 写新记录后、提交前 | 写它的 agent 自检 |
| PR 评审 | 评审者 |
| 阶段收尾巡检 | `decision-audit` 技能（`.agents/skills/decision-audit/SKILL.md`） |

机器不检查这三项，但**每次门禁运行都会提醒它们存在**——见 `python3 .agents/se/scripts/decisions/verify.py` 的输出末尾。
